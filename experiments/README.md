# experiments/

Scripted scenario fixtures and the Runner's own experiment output for local and Base Sepolia runs
(spec 15.3, task 8).

## `fixtures/scripted/`

Eight `fleet.fixture.v1` fixtures (`@fleet/schemas`'s `FixtureV1`; see `apps/runner/README.md` for
the schema itself), matching spec 15.3's scenario table:

| Fixture | What happens | Expected outcome |
| --- | --- | --- |
| `hf-replay` | An agent proposes fetching solutions from a non-allowlisted host | Defeated; the gateway keeps blocking the fetch |
| `legit-amendment` | An agent proposes adding one legitimate, needed host to the allowlist | Executed; charter version 2; the gateway then allows the action |
| `delegation-visible` | Two members delegate to a third before a vote | Succeeded, with the delegatee's weight visibly carrying the extra votes |
| `impostor` | An unregistered signer attempts to propose and to vote on the real proposal | Both attempts revert (`HookCallFailed`), recorded, alongside a normal proposal that still runs to Defeated |
| `guardian-cancel` | A succeeded proposal is queued; the guardian pauses the ledger and cancels the queued timelock operation | Canceled; nothing is ever recorded |
| `late-vote` | One worker's vote misses the submission-margin window | 4 of 5 votes recorded, 1 missing, still Succeeded |
| `three-unavailable` | Three of five workers are offline | Defeated; quorum cannot be met |
| `two-colluding` | Two workers always vote For a deviation; the rest vote Against | Defeated at N equals 5 |

`fleet demo` runs these eight, in the order listed above, on one fresh fleet deployment, each on
its own fresh task. `fleet run` drives a single fixture named by a `fleet.experiment.v1` config's
`scenario.fixture` field.

Every fixture's task is opened with the same base charter (`apps/runner/src/demo.ts`'s
`DEMO_TASK_CHARTER`): allowed classes `read_repo`, `write_repo`, `run_tests`, `package_install`,
`network_fetch`; external allowlist `registry.npmjs.org`; budget 200 tool calls. `legit-amendment`'s
`trigger.newCharter` is that same charter with one host (`pypi.org`) appended to the allowlist, so
its `gatewayAfter: "ALLOW"` check is exercised against exactly the host the amendment adds.

## `reports/`

Default base directory for `fleet run`, `fleet capture`, `fleet report`, and `fleet demo`'s
`--report-dir` (per run: `<run id>/record.json`, `<run id>/report.md`, and, for a JSON-file-backed
run, `<run id>/run-state.json`). Not committed; generated by running the Runner.

## Reproducing a run

`fleet capture --run-id <id> --from-chain --rpc <url>` rebuilds a run's chain-derived record
sections (`events[]`, `votes[]`) purely from the deployment's chain logs; the demo's own
integration test (`apps/runner/src/demo.integration.test.ts`) asserts this reproduces the live
run's `events[]` and `votes[].onchainReason` exactly.
